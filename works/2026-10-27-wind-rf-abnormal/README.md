# 基于随机森林的风电机组出力工况识别与异常预警

日期：2026-10-27  
slug：`wind-rf-abnormal`  
关键词：风电，随机森林，异常预警

## 今日切入

主题队列下一条是用随机森林识别风电机组出力工况，并在故障日志之前给出异常预警。机组 SCADA 里，风速、功率、转速、桨距角和齿轮箱 / 机舱温度本来就是运行人员每天看的量；厂家功率曲线把「这一风速下该发多少电」画成一条带，持续偏离这条带、或温度相对功率偏高，往往比停机记录更早出现。2024–2026 年公开工作一边放出带故障标注的 10 min SCADA 基准，一边用随机森林及其与 XGBoost 的混合模型做可解释检测。本篇做方法速览，方便在新能源课上先跑通「功率曲线贴标签 / 正常行为回归 → 森林 → 误报与提前量」这条闭环。

## 背景 5 分钟

**电气问题。** 稳态出力由风速、空气密度、桨距角和转速共同决定。低于切入风速时机组不发电，额定风速附近功率被限在额定值附近，高于切出则停机。厂家功率曲线是这条关系的标称形状。现场 SCADA 多为 10 min 平均：同一风速下功率会因湍流、偏航误差、结冰、调度限电和传感器漂移而散开。齿轮箱油温、轴承温度和机舱温度还有热惯性，功率和转速升上去之后温度才慢慢跟上；冷却不良时，温度相对当时的功率和转速偏高。工况识别要先把正常发电、限功率、停机、启动过渡分开。限电和计划停机并进「故障」类，预警就会对着调度指令报警。预警要回答的是：在故障记录时刻之前，残差或类别概率能否持续越限，以及提前了多久；已经停机的点再分类，只是事后核对。

**AI 方法。** 随机森林对自助样本各长一棵决策树，分类时投票，回归时平均。它不要求特征标准化，也能给出基于不纯度下降的特征重要度，适合几十到几百列的 SCADA，也方便和单棵树、逻辑回归或 XGBoost 对照。课堂上两条接法就够用。一是工况分类：用状态码或功率曲线分箱给每个 10 min 点贴「正常出力 / 限功率 / 停机 / 疑似异常」，森林输出类别。二是正常行为回归：只用确认正常的时段学习「风速、转速、桨距 → 功率」或「功率、转速 → 齿轮箱温度」，再用残差超过阈值做预警。森林不描述温度的热动态；残差按单点判断时，湍流尖峰会变成误报。异常点远少于正常点时，准确率会被正常类抬高。训练和测试必须按时间切开，不能随机打乱，否则同一故障过程的前兆和结果会同时出现在两边。

## 方法草图

**输入**

- 10 min SCADA，优先用各通道的平均值：风速 $v$、有功功率 $P$、转子转速 $\omega$、桨距角 $\beta$、齿轮箱温度 $T_{gb}$、机舱温度 $T_{nac}$。可选环境温度、风向偏差、发电机转速。
- 派生量：相对功率曲线的偏差 $P - \hat{P}_{pc}(v)$；温度相对功率、转速的偏离；短窗内的斜率。桨距角若出现 $0^\circ$ 与 $360^\circ$ 缠绕，先把角度折回连续区间再送进树。
- 工况标签：来自状态码，或来自功率曲线分箱（按风速分箱，正常发电段的功率落在分位带内；带外且状态仍为发电，标为疑似出力异常）。限功率、维护停机单独成类。
- 时间对齐与切分：按时间排序。训练时段整体早于测试时段。故障前的预警窗口不要跨进训练集。标准化若要做，统计量只用训练段。

**模型或算法**

分类基线：随机森林分类器，输入当前点或短窗统计，输出工况。类别不平衡时使用类权重，或对正常类下采样；树的棵数先取一两百，最大深度设上限，避免记住单台机组的噪声。票数比例可当作粗糙的置信度，阈值用验证段的误报率来定，而不是固定 0.5。

预警基线：正常行为回归。只用标成正常发电的训练行拟合随机森林回归器，目标取 $P$ 或 $T_{gb}$。残差 $r = y - \hat{y}$。阈值取训练残差的高分位，或滚动中位数加减若干倍 MAD。连续 $m$ 个 10 min 点越限才报警，用来压低单点湍流。提前量定义为故障记录时刻减去首次持续报警时刻；报警落在记录之后则记为偏晚。分类和回归可以前后串联：先认出限电和停机并排除，再对「应当正常发电」的点做残差检验。

和梯度提升树混合、再用 LIME 看单次报警被哪些特征推高，是 2025–2026 年公开论文里的进阶路线。课堂先把单模型随机森林跑通，再决定要不要加第二级模型和局部解释。局部解释用来核对「报警是不是由温度或功率残差推高」，不把解释当成冷却系统的因果证明。

**输出与指标**

- 分类：按类报告精确率、召回率、F1。另报误报率，即正常点被判成异常的比例。准确率只作附属，因为正常类占多数时它会很高。
- 预警：事件级命中（一次故障只要在提前窗口内持续报警一次即算检出）、正常运行日上的误报次数、预警提前时间的中位数和分布。
- 对照：功率曲线分位带规则、单棵决策树、同一特征上的逻辑回归或浅层阈值规则。
- 约束是否被遵守：限电是否被单独成类、测试是否严格晚于训练、报警是否要求连续越限。

下面是课堂用的离散草图，不是某一篇论文的训练代码。

```text
# 10 min SCADA; prefer Avg channels
sort by time
train = earlier days; test = later days          # no shuffle
# route A: operating-state classification
y = status code or power-curve bin
    # normal production / curtailed / stopped / suspect
    # keep curtailment out of the fault class
rf_clf.fit(X_train, y_train)                     # class_weight or downsample majority
report per-class precision, recall, F1, and false-alarm rate on test
# route B: normal-behavior regression + residual warning
fit rf_reg on train rows labeled normal only     # target = P or T_gearbox
r = y - rf_reg.predict(X)
thr = high quantile of train residuals           # or rolling median +/- k * MAD
alarm if r stays beyond thr for m consecutive steps
lead time = fault_log_time - first persistent alarm
baselines: power-curve quantile band, one tree, logistic regression
```

## 最新公开信息

1. **CARE to Compare：带故障标注的风电 SCADA 基准（期刊 2024-11-23，预印本 2024-04）。** Gück、Roelofs、Faulstich（Fraunhofer IEE）在 *Data* 9(12):138 发表数据集论文，预印本为 arXiv:2404.10320。数据来自 3 座风场、36 台机组，共 95 个子集、合计 89 年的 10 min SCADA。期刊与预印本摘要写明：44 段通向故障的异常时段，以及 51 条正常行为序列；每个子集含约一年训练数据和 4–98 天的预测段，并用机组状态为每个点提供标签。文中提出 CARE 分数（Coverage, Accuracy, Reliability, Earliness），同时看检出、正常行为识别、少误报和提前发现。风场 A 基于 EDP 开放数据，为葡萄牙陆上风场的 5 台机组，从中选了 22 个子集；风场 B、C 为德国海上风场，已匿名。论文早期版本指向的数据记录更旧，课堂下载请用下面的 v6。摘要中的 44 / 51 与 v6 页面上的 45 / 50 不一致，原因见下条版本说明，引用时要写清论文还是数据版本。  
   https://arxiv.org/abs/2404.10320  
   https://doi.org/10.3390/data9120138

2. **Zenodo「Wind Turbine SCADA Data For Early Fault Detection」v6（2025-07-09，CC BY-SA 4.0）。** Gück 与 Roelofs 发布的数据集，DOI 为 10.5281/zenodo.15846963，与上条论文配套。记录写明 95 个子集、36 台机组、3 座风场、89 年 10 min 数据；风场 A / B / C 的特征数分别为 86、257、957。v6 说明中的平衡关系是 45 个子集含通向故障的异常事件、50 个为正常行为。版本说明写明：v5 把风场 A 的事件 51 从「正常」改成异常，原因是预测段内有齿轮箱轴承损伤，这就是 44 / 51 变成 45 / 50 的来由。同一页的已知问题：各时刻的 Min、Max、Std 常出现不合理组合，Avg 大体可用；风场 A 的桨距角有 $0^\circ$ / $360^\circ$ 缠绕。风场 A 的 `status_type_id` 来自 EDP 故障日志，记录建议用它过滤训练数据，在用 CARE 等指标评估预测时段时可以忽略，避免把事后日志当成当时已有的特征。记录中给出的 EDP 平台链接本次检索返回 404，作业直接使用本记录即可。  
   https://zenodo.org/records/15846963  
   https://doi.org/10.5281/zenodo.15846963

3. **随机森林–XGBoost 混合 + LIME 的风电机组故障检测（开放获取，*Results in Engineering* 2025 年第 28 卷，文章编号 107446）。** Rengasamy 与 Rajesh 用印度某风场的实时 SCADA 做异常检测；文中亮点写明对象为一台 750 kW 机组。流程包括 SelectKBest 筛选特征、SMOTE 处理类别不平衡、RandomizedSearchCV 调参，再把随机森林与 XGBoost 组成混合模型，并用 LIME 做局部解释。摘要给出的调优结果为准确率 0.9995、F1 0.9995，MAE 与 MSE 均为 0.00052。LIME 把机舱温度和齿轮箱温度标成制动类事件的关键指标，作者据此讨论冷却系统维护。这些数字属于该文的机组、标签和划分，不能抄成课程验收线；温度重要度说明热工量值得放进特征表，并不自动证明「改冷却器就能消除报警」。  
   https://doi.org/10.1016/j.rineng.2025.107446  
   https://www.sciencedirect.com/science/article/pii/S2590123025035017

4. **物理信息混合模型：随机森林–XGBoost 堆叠 + 疲劳指标（开放获取，2026）。** Omar、Mosbahi、Ben Jdidia 等在 *Shock and Vibration* 2026 年第 1 期（DOI 10.1155/vib/3021162；Crossref 许可起始日为 2026-07-24）用土耳其 Yalova 风场 SCADA，把随机森林与 XGBoost 的堆叠模型和基于 Palmgren–Miner 的疲劳指标放在一起，用 Optuna 调参，并用 SHAP 看全局重要度、LIME 看单点解释。摘要报告 F1 0.9992、召回率 0.9996、精确率 0.9989、ROC–AUC 1.0000，同时写明这些标签来自对 SCADA 变量的阈值规则，结果需要谨慎解读。SHAP 与 LIME 把风速和功率偏差标为异常的主要驱动，疲劳累积只是调制项。这篇适合放在课堂最后：当标签本身由阈值生成时，极高的 F1 主要说明模型复现了规则，应把提前量、误报和标签来源一起报告。  
   https://doi.org/10.1155/vib/3021162

## 教辅提示

**小实验。** 用 Zenodo v6 的风场 A（特征较少，且能对照功率、风速、桨距、温度这类物理量；优先读 Avg 列）。固定同一段更晚的测试周，做三组对照：功率曲线分位带规则、随机森林工况分类、只用正常发电段训练的随机森林回归加残差预警。分类至少包含正常发电、限功率、停机、疑似异常四类。报告按类精确率、召回率、F1 和误报率；若 `event_info` 里有故障时刻，再报事件级命中和预警提前时间。然后故意把同一次实验改成随机打乱后的训练 / 测试，把两套指标并排贴在一张表里，看泄漏把数字抬高多少。有余力再对一次报警做 LIME 或查看森林重要度，核对推高报警的是不是功率残差或齿轮箱 / 机舱温度。

**常见坑**

- 按样本随机划分。同一故障的前兆在训练集、结果在测试集，F1 会很好看，提前量却没有意义。
- 把调度限电、计划停机并进故障类。模型学到的是「功率低」，不是设备异常。
- 用含测试时段的全局均值和方差做标准化，或把未来状态码、事后故障日志当作当时的输入。风场 A 的 `status_type_id` 尤其容易踩到。
- 只报准确率。正常点占绝大多数时，全部判正常也能得到很高的准确率；要看异常类召回和误报率。
- 残差单点越限就报警。湍流和通信毛刺会把误报次数打满；要求连续若干个 10 min 点，并在验证段选定 $m$ 和阈值。
- 直接使用 Min、Max、Std。v6 记录写明这三列经常不合理；课堂分析以 Avg 为主。桨距角要先处理 $0^\circ$ / $360^\circ$ 缠绕。
- 把摘要里的 0.9995 或 0.9992 抄成验收线。对象、标签来源和划分都不同；标签若由阈值生成，高分只说明模型贴近那条规则。
- 森林预警不代替振动监测、过速保护和变桨安全链。温度重要度升高，只说明该把热工量放进检查清单。
