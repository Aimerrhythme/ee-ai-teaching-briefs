# 基于聚类的工业园区典型用电负荷模式识别

日期：2026-10-28  
slug：`park-load-clustering`  
关键词：聚类，负荷模式，工业园区

## 今日切入

主题队列下一条是用聚类识别工业园区的典型用电负荷模式。园区关口上叠着连续生产、白班加工、办公楼和公辅设施，只报最大需量时，「全天高而平」和「白天单峰」会被当成同一种负荷。2023–2025 年公开工作沿三条能进课堂的路线：用加权 K-means 把工、商业行业曲线收成可公开的小时典型曲线；用 DTW 距离的 K-means 按形状分开日负荷；用密度与层次方法从制造园区全年负荷里挑典型日，再交给综合能源规划。本篇做方法速览，方便在负荷特性课上先跑通「日曲线归一化 → 距离 → 聚类数 → 典型曲线命名」这条闭环。

## 背景 5 分钟

**电气问题。** 一条日负荷曲线是某一对象在一天里的有功序列。15 min 采样是 96 点，1 h 采样是 24 点。连续工艺的曲线接近平坦，负荷率高；机加和装配多在白班形成单峰，午休减产时变成双峰；办公和研发楼通常早上升、午间回落、傍晚下降；三班倒会把峰挪到夜间。检修、限电和法定节假日则是另一类「低而平」或整段缺失。典型曲线把一年里几百条日曲线收成少数几条，供需量讨论、分时电价举例和规划里的典型日选取。它回答的是「这一天像哪一种生产日」，不是下一小时功率预测，也不是保护整定。

对象必须先说清。园区关口总加会把各厂房的错峰抹平，适合看园区整体的典型日，不适合声称已经认出了「机加模式」和「办公模式」。单用户或单回路曲线才能把班制分开。工作日、周末和节假日若放进同一个池子，中心会被停机日拉低，正常生产的峰被稀释。

**AI 方法。** K-means 把每条日曲线看成固定长度向量：把样本分到最近中心，再把中心更新为该类均值，直到分配不再变化。默认距离是欧氏距离，同一时刻的数值接近才算近。整条曲线的班次提前或推后一两个小时时，形状很像，欧氏距离却很大。动态时间弯曲（DTW）允许时间轴局部伸缩，用一条对齐路径上的累计代价衡量形状；DTW-K-means 用这个代价代替欧氏距离。此时「中心」应是使类内 DTW 代价最小的那条序列，逐点平均只是便于画图的近似，尖峰会被抹开。

密度聚类不预先指定类数，可以把孤立的检修日标成噪声，但邻域半径和最少点数很敏感，类重叠时轮廓系数可以为负。轮廓系数越高越好，Davies–Bouldin 指数越低越好，Calinski–Harabasz 指数越高越好。这三项只说明几何上紧不紧、分得开不开，不说明「这一类是不是白班机加」。肘部和轮廓系数给出的类数经常不一致，最终要回到中心曲线的峰时和天数占比。

## 方法草图

**输入**

- 一条样本是一个对象、一天的有功。全文固定对象：园区关口、一回馈线或一个用户，三者不要混在同一次聚类里。
- 清洗：缺测、通信中断和全零日先剔除，或单独标成「无效日」。不要用前后日的均值填出一条看起来正常的曲线。检修和计划停机可以留在样本里，但要有标记，聚类后再核对它们是否自成一类。
- 归一化决定比的是形状还是大小。比形状时，用当日最大值把曲线收到 $[0,1]$，或做成零均值、单位方差。比需量时保留 kW，大用户会独占中心。两种结果不要放进同一张验收表。
- 日历：工作日、周末、法定节假日先分组再聚类，或聚类后用日类型解释。不要指望欧氏距离自己学会日历。

**模型或算法**

课堂基线是欧氏距离 K-means。类数 $K$ 从 2 扫到 8 左右；每种 $K$ 换若干组初始中心，留下类内平方和最小的一次。肘部看畸变下降开始变缓的位置，轮廓系数看样本更靠近自己的中心还是邻类。两条曲线不一致时，把候选 $K$ 的中心都画出来，按「平坦高负荷、白班单峰、双峰、夜间生产」命名，选用解释得通的那个，并写明另一指标推荐的 $K$。

形状对照用 DTW-K-means：同一批归一化曲线，距离换成 DTW。96 点序列建议限制对齐路径偏离对角线的宽度，否则两两对齐既慢，也会把不相干的峰硬拉到一起。展示用的典型曲线可以再取类内逐点中位数，用来压低单日尖峰；报告里要写明它是展示曲线，不一定是 DTW 目标函数的精确中心。

第三对照用不预设类数的密度聚类，报告噪声点占比。噪声很多时，先分清是参数过严，还是数据里确实有大量停机日。

**输出与指标**

- 内部指标：轮廓系数、Davies–Bouldin、Calinski–Harabasz，以及肘部使用的类内距离和。
- 形状：类内曲线与中心的相关系数，以及峰、谷落在哪些时段。
- 解释：每一类的天数占比、工作日占比、平均日电量、峰谷差。能对上班制才算完成。
- 对照：欧氏 K-means、DTW-K-means、一种密度聚类。三者用同一批曲线、同一种归一化。
- 稳定性：更换初始中心，或换相邻月份重做，看同一类中心的峰时是否还在。

下面是课堂用的离散草图，不是某一篇论文的训练代码。

```text
# one sample = one object's active-power curve for one day
# 96 points at 15 min, or 24 points at 1 h
drop incomplete days and all-zero days
tag weekday / weekend / holiday; cluster weekdays first
X = curve / daily_max                 # shape. do not mix with raw kW
for K in 2..8:
    fit Euclidean K-means several times; keep the lowest inertia
    record inertia, silhouette, Davies-Bouldin, Calinski-Harabasz
# if elbow and silhouette disagree, plot both candidate centroids
# DTW variant: same X, distance = DTW with a limited warping band
# plot the class mean and the pointwise median; say which is which
# density baseline: mark sparse days as noise and report the noise share
name each cluster from centroid shape, day share, and mean daily energy
```

## 教辅提示

**小实验。** 下载 ELMAS 的 18 条簇曲线（或其中按小时平均后的日形态）。固定「按各自最大值归一化」，做三组对照：欧氏 K-means、DTW-K-means、一种不预设类数的密度聚类。$K$ 至少比较肘部推荐值和轮廓系数推荐值。每条中心曲线注明峰时、谷时和它在 18 条里代表的天数或电量权重要从数据文件里读，不要凭印象命名。然后故意改一次：不做归一化，或把周末与工作日混在一起，把两套中心曲线贴在同一张图里，看大数值和日历怎样把形状冲掉。有余力再对 DTW 结果同时画出逐点均值和逐点中位数。

ELMAS 只有十几条已聚合曲线时，聚类会过于容易。可以把它当作「标准形态库」：另用正弦叠加、白班矩形波、平坦高负荷和夜间班次生成带噪声的 96 点日曲线，看算法能否把这四种形状找回来，再用 ELMAS 的真实形态做对照，而不是用仿真曲线冒充园区实测。

**常见坑**

- 用园区总加代替用户曲线，再把簇命名成「某类工厂」。总加已经抹平了错峰。
- 保留 kW 做聚类。容量大的对象主导中心，形状相近的小用户进不了同一类。
- 用含待检验日期的全局均值和方差做标准化。留出月份做稳定性检验时，统计量只用其余日期。
- 肘部和轮廓系数不一致时只报一个数。*Energies* 一文里肘部是 4–6 类、轮廓系数偏向 2–3 类，作者另选了 2 类并说明理由。
- 把 DTW 的类中心画成逐点均值，却按精确 DTW 中心来解释尖峰。尖峰可能是平均出来的，中位数图要分开标注。
- 停机日、缺测填补日和正常生产日放在一起。中心会被拉向低负荷。
- 轮廓系数 0.630、随机森林准确率 0.78、或 200/208 的 96%，抄成验收线。对象、样本是「日曲线」还是「小时点」、以及是否含人工归类，都不相同。
- 把 ELMAS 人工归并后的 18 类说成肘部自动选出的类数。肘部在 16，后两类来自人工重组。
- 同一行业代码就认为曲线相同。ELMAS 专门说明，同一 NACE 门类里的日、周形态可以差很多。
- 内部指标高，就据此修改变压器容量或报装需量。聚类结果是形状分组，容量核算还要回到 kW、同时率和持续时长。

**延伸阅读。** 先读 ELMAS 论文里特征怎么由小时、日、周平均拼出来，以及 16 类到 18 类的人工归并，再下载 figshare 上的曲线文件。DTW 与密度聚类的指标冲突，以 *Energies* 一文的 Table 7 讨论和 2 类中心图为准。园区典型日如何进入规划，读 *Frontiers* 一文第 3 节，并记下表号不一致。
