# 风机功率曲线异常点识别与清洗（2026-11-27）

> 主题：`wind-power-curve-cleaning` · 关键词：风电、功率曲线、异常数据、数据清洗  
> 定位：教辅 / 技术速览，供课堂与课题讨论参考；不是毕业论文代写。

## 1. 今日切入

**一句话**：风电 SCADA 的「风速—功率」散点里常混着限电、停机和传感器故障造成的异常点；不先把它们洗掉，拟合出的功率曲线、发电量评估和后续的预测/预警模型都会被系统性拉偏——**先洗数据，再建模**。

**为何今天写**：本仓 10-27 的 `wind-rf-abnormal` 讲了用随机森林做工况识别与异常预警，但默认「正常点已经挑好了」。今天往前补一步：这些正常点怎么挑出来。用纯 numpy 合成数据把**规则预清洗 → 分箱统计法（均值±σ / 中位数±MAD / 四分位）→ 图像（形态学）法**放在同一张表里比较，并专门造一个「重度限电」场景，让学生看到分箱统计法在什么条件下会失效。

## 2. 背景 5 分钟

**电气问题**：风机稳态出力由风速决定，理论上沿着一条 S 形功率曲线：低于切入风速不发电，切入到额定风速之间近似按风速三次方增长，额定风速以上靠变桨把功率限在额定值，超过切出风速停机。现场 SCADA 一般是 10 min 平均值，同一风速下功率本来就有散布（湍流、空气密度、偏航误差），此外还有几类「不是机组本来能力」的点：
- **负值点**：风速已超过切入，功率却为负（停机时的自耗电、变送器零漂）；
- **堆积点**：调度**限电**时功率被压在某个水平带上，散点图里是一条横带；**停机**/检修时中高风速下功率≈0，是贴着横轴的一条带；
- **分散点**：风速计结冰或故障、通信异常造成的零散点，散落在主曲线下方。

功率曲线测试的标准做法（IEC 61400-12-1 的**分箱法**）是把风速按 0.5 m/s 分箱，每箱求功率平均值连成曲线，再结合风速分布算年发电量（AEP）。分箱平均对异常点非常敏感：限电带和零功率带都会把箱均值往下拉，直接表现为「机组性能变差」的假象。

**AI / 数据方法**：
- **规则法**：按物理常识直接筛（负功率、中高风速零功率、超出额定的不合理值），简单、可解释，但只能抓「明显不可能」的点；
- **分箱统计法**：每个风速箱内用均值±kσ、中位数±k·MAD 或四分位距（IQR）判离群；开源库 OpenOA 的 `bin_filter` 就是这一类，支持 `std` / `mad` / `scalar` 阈值与 `mean` / `median` 中心；
- **聚类 / 距离法**：如 k-means、局部离群因子（LOF），或 OpenOA 的 `cluster_mahalanobis_2d`（先 k-means 聚类再用马氏距离判离群）；
- **图像法**：Long 等（2020，见第 4 节）把散点图当成**二值图像**，用数学形态学运算提取「主体」部分，再把像素映射回数据点打标签——它不依赖每个箱内「正常点占多数」的假设，对成片的堆积点更稳。

## 3. 方法草图

**输入**：10 min SCADA 的 (风速 v, 有功功率 P)，可选桨距角、转速、状态码。  
**流程（概念级）**
```
1 规则预清洗：v > 切入 且 P < 0 → 负值点；5 < v < 切出 且 P ≈ 0 → 停机点
2 二选一或串联：
  a 分箱统计：for 每个 0.5 m/s 风速箱：中心 c（均值/中位数），离散度 s（σ/MAD/IQR）；|P − c| > k·s → 异常
             （样本太少的箱跳过；中位数+MAD 可迭代几轮）
  b 图像法：散点 → 栅格化二值图 → 开运算（先腐蚀后膨胀）去掉细碎散点与细横带
           → 沿风速方向跟踪与主体相连的连通段 → 主体外像素对应的点判异常
3 用保留下来的点按分箱法求功率曲线，算 AEP，或交给后续预测/预警模型
```
**评价指标**：有标签（合成或人工标注）时看精确率 / 召回率 / F1、**正常点误删率**；没有标签时看清洗后功率曲线与厂家保证曲线的偏差、AEP 变化、剔除率是否合理（剔除过多会把真实性能退化也洗掉）。

**本目录附带的合成数据演示**：[`wpc_cleaning_demo.py`](./wpc_cleaning_demo.py)（仅依赖 numpy，本机约 0.3 s）  
合成 1 台 2 MW 机组一年 52560 个 10 min 点（风速 Weibull k=2、c=8 m/s；切入/额定/切出 3/12/25 m/s；正常点按真实曲线加噪声），注入负值点 700 个、停机点 1200 个、分散点 900 个，限电段（功率压在约 1000 kW 平台、每段 30–150 个连续点）在**场景 A 取 40 段、场景 B 取 250 段**。「RMSE」为清洗后分箱平均曲线与真实曲线的均方根偏差（kW），「AEP 偏差」按同一 Weibull 风况计算（真实曲线 AEP = 7171 MWh）。

读法：
1. **不洗数据的代价是看得见的**：场景 A 只有 7.4% 的异常点，就让分箱功率曲线在 3–15 m/s 段平均偏低约 143 kW、AEP 低估 8.5%；场景 B 低估到 17%。如果拿这条曲线去评估「机组性能退化」或训练功率预测模型，结论会被直接带偏。
2. **规则法精确率 100% 但只抓到一半**：负值点和零功率停机点全部抓到，限电平台和分散点几乎抓不到（分散召回 0.01）——规则只能处理「物理上不可能」的点。
3. **常规场景下分箱统计法够用**：三种分箱法 F1 都在 0.81–0.93，3–15 m/s 段曲线误差降到 12–14 kW，AEP 偏差在 ±0.4% 内。其中 IQR 误删最少（0.32%）；中位数±MAD 迭代 3 轮召回略高但误删也最多（2.55%）——阈值 k 和迭代轮数本质上是在「漏检」与「误删」之间取舍。
4. **分箱法的前提是「每个箱里正常点占多数且单峰」**：场景 B 中限电点在 10–25 m/s 的箱里占了很大比例，箱内分布变成「额定功率一团 + 1000 kW 一团」的双峰，均值和 σ（或 IQR）都被撑大，于是限电带被当成「正常的散布」——均值±2σ 和 IQR 的召回跌到约 0.25，几乎和不清洗一样。中位数+MAD 更稳健一些，迭代后召回 0.61，但仍留下大段偏差。
5. **图像法换了一个角度**：它不在箱内做统计，而是找散点图里「连成一条曲线的主体」，限电横带即使点数多，只要和主体在图上不连通、且被开运算削掉，就会被剔除；两个场景下 F1 都在 0.87–0.92，曲线误差 6–18 kW。**但注意**：这里的图像法是本文按 Long 等的思路写的简化版（栅格大小、密度阈值、跳变上限都是在这份合成数据上手调的），不是原文算法的复现；参数换一台机组可能就要重调，这正是图像法在工程上的主要成本。
6. **高风速段是所有方法的软肋**：RMSE 3–25 m/s 明显大于 3–15 m/s，因为 Weibull 风况下 18 m/s 以上的点很少，箱内样本不足（演示里 <10 个点的箱直接跳过统计判别），残留的一两个异常点就能把箱均值拉偏几百 kW。IEC 分箱法对每箱的最少数据量有要求，工程上也常对高风速箱做合并或外推。

合成数据远比真实 SCADA 简单（风速逐点独立、异常类型和比例都由脚本设定），数字只用于课堂讲清概念，不代表任何真实风电场或文中引用方法的性能。

## 4. 最新公开信息

1. **Image-Based Abnormal Data Detection and Cleaning Algorithm via Wind Power Curve**（Huan Long, Linwei Sang, Zaijun Wu, Wei Gu；*IEEE Transactions on Sustainable Energy* 11(2): 938–946, 2020-04，DOI 10.1109/TSTE.2019.2914089；arXiv:2307.08539，2023-07 上传）  
   本主题的核心参考。摘要：把风机异常数据分为**负值点、分散点、堆积点**三类；算法分三步——数据预清洗（先滤掉风速大于切入但功率为负的点）、正常数据提取（把其余散点画成功率曲线图像及其二值图，用**数学形态学运算**提取代表正常数据的主体部分，形态学参数通过最小化提取结果与参考功率曲线图像之间基于 **Hu 矩**的差异来确定）、数据标记（依次识别分散点和堆积点对应的像素，再通过点—像素映射关系给原始数据打正常/异常标签）。文中与 k-means、局部离群因子（LOF）以及「变点分组 + 四分位」组合算法对比，在两个风电场 33 台机组上验证有效性、效率和通用性。  
   https://arxiv.org/abs/2307.08539 · https://doi.org/10.1109/TSTE.2019.2914089

2. **OpenOA 开源库**（风电场运行分析的 Python 开源框架；BSD-3-Clause；最新发布 v3.2，2026-01-30；配套论文 Perr-Sauer 等, *OpenOA: An Open-Source Codebase For Operational Analysis of Wind Farms*, *Journal of Open Source Software* 6(58): 2171, 2021，DOI 10.21105/joss.02171）  
   `openoa/utils/filters.py` 里直接提供了本文提到的几类清洗工具：`range_flag`（量程越限）、`unresponsive_flag`（数据连续若干个周期不变，常见于传感器卡死）、`window_range_flag`（指定风速窗口内功率越限，可用于抓中高风速零功率）、`bin_filter`（分箱离群判别，阈值可选 `std` / `scalar` / `mad`，中心可选 `mean` / `median`，可只判上方或下方）、`cluster_mahalanobis_2d`（k-means 聚类 + 马氏距离）。适合本科/专升本把本文的 numpy 演示换成「工程库 + 真实数据」再做一遍。注：GitHub 上原 `NREL/OpenOA` 地址现会跳转到 `NatLabRockies/OpenOA`（2026-11-27 查看）。  
   https://github.com/NatLabRockies/OpenOA · https://doi.org/10.21105/joss.02171

3. **XAI for transparent wind turbine power curve models**（Simon Letzgus；arXiv:2210.12104，2022-10；ICLR 2023「Tackling Climate Change with Machine Learning」workshop 论文）  
   清洗之后的下一步——用机器学习建功率曲线模型。摘要：用 Shapley 值等可解释 AI（XAI）方法分析在真实运行数据上训练的功率曲线模型学到了什么策略，发现一味追求测试集精度、模型越做越大，可能学出**物理上不合理**的策略，因此主张在模型选择时更多使用 XAI；并提出用解释结果做风机性能监测中的根因分析。可以和本文合起来讲：数据里残留的限电/停机点，也正是模型学到「怪策略」的常见来源之一（这是本文的教学引申，不是该论文的结论）。  
   https://arxiv.org/abs/2210.12104

## 5. 教辅提示

**可布置的小实验（2–4 学时）**
1. 运行 `wpc_cleaning_demo.py`，先只看「不清洗」与「仅规则预清洗」两行，让学生解释为什么规则法精确率 100% 却只抓到一半异常。
2. 把场景 A 的限电段数从 40 逐步加到 80、120、160、250，画出「均值±2σ」和「IQR」的召回率曲线，找出分箱统计法开始失效的大致限电比例，并解释双峰分布为什么会撑大 σ 和 IQR。
3. 改阈值：均值±kσ 的 k 取 1.5 / 2 / 3，IQR 的系数取 1.0 / 1.5 / 3，画「召回率—正常误删率」曲线，讨论现场更怕漏检还是更怕误删（误删过多会把真实的性能退化也洗掉）。
4. 用 matplotlib 画出清洗前后的散点图，并把图像法中间结果（二值图、开运算后的图、提取出的主体）逐张画出来，直观理解「腐蚀—膨胀」各起什么作用。
5. 本科 / 专升本延伸：用 OpenOA 自带的示例风电场数据（La Haute Borne，Engie 公开）调用 `range_flag`、`window_range_flag`、`bin_filter`、`cluster_mahalanobis_2d` 做清洗，与本文 numpy 实现对比；再把清洗前/后的数据分别喂给本仓 10-27 的随机森林工况识别或一个功率预测模型，量化「先洗数据」对下游模型误差的影响。

**常见坑**
- **把限电当故障、把故障当限电**：限电是调度指令造成的，机组本身没毛病；如果有调度/限功率记录或状态码，应优先用它们打标签，统计方法只做补充。
- **清洗过度**：剔除率过高（例如 >20% 且没有对应的限电/停机记录）往往意味着阈值过严，或者机组真的有性能退化——清洗算法会把「病」也当成「噪声」洗掉。
- **高风速箱样本少**：箱内点数少时统计量不可靠，应合并箱或设最小样本数，不能对两三个点算 σ。
- **只看散点图不看时间**：限电和停机通常是**连续时段**，结合时间连续性（如连续 N 个点功率不变、平台持续时间）能显著提高识别率，OpenOA 的 `unresponsive_flag` 就是这个思路。
- **忽略空气密度**：严格的功率曲线要先把风速按空气密度归一化，冬夏密度差会让曲线整体平移，被误判为异常。
- **图像法的参数迁移**：栅格分辨率、阈值、结构元大小与机组额定功率、数据量强相关，换机组要重新标定。
